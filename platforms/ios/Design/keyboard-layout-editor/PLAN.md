# 自定义键盘布局：交互原型与接入计划

日期：2026-10-02。当前阶段先确认编辑方式；本目录的原型不修改 iOS 键盘、不接入 Rime，也不代表共键布局已经能输入中文。

2026-10-02 更新：用户已要求接入首版原生编辑器与导入入口。实现及验证范围见 [原生版验证记录](../../validation/custom-layouts-20261002.md)；下文保留原始分阶段计划，不能把未完成阶段视为已交付。

## 现用并击布局的兼容要求

用户已经调试好日常使用的正交并击键位。新增自定义布局必须保留这套实际手感，作为原生接入的硬性验收条件。

- 第一批原生自定义布局只作用于普通输入模式。并击继续走现有布局和触摸处理路径，不自动转换成新模板，也不被普通布局的键高、间距、槽位或功能键设置覆盖。
- 保留并击的左右键区、键位顺序、键宽键高、间距、触摸范围、滑动与多点触摸判定、功能键位置以及触感设置。并击内切换英文、数字、表情以及打开 Buffer 时，同样保持现有行为；不能只保护正在解析并击的瞬间。
- 普通布局使用独立的新配置字段和适用范围，保留现有 `chord`、`profiles`、`chordLayout` 等值。新字段缺失、损坏或版本不支持时只回退该布局，不得导致整份配置重置并丢失并击方案。
- 隔离条件按所属输入方案判断，而不是按 `resolvesChords` 判断。编辑或保存普通布局不得改变 `schemeSelectionRevision`、重选并击方案或退休正在进行的并击触摸；在并击模式收到普通布局修订时只缓存，切入适用的普通模式后再使用。
- 实施前记录并备份手机实际使用的并击方案和扩展私有偏好，以及对应的键盘几何基线；不能用电脑上的默认配置代替手机实际配置。当前原型阶段尚未执行这份设备备份。
- 回归应在相同屏幕宽度、方案、输入状态下比较新旧并击键框、命中区和总高度，并覆盖横竖屏、普通模式往返切换、长按删除、滑动、多指输入及 Buffer 开关；自动化通过后仍需用户确认真机手感。
- 若以后开放并击布局编辑，入口采用“复制现用布局再编辑”，原布局保留可恢复；只有用户明确应用副本才切换。

## 第一版要确认什么

从模板开始，选键盘模板和槽位结构，把键放到槽位中，调整紧凑程度和功能键，立即预览效果。允许用户先完成一个不完整的草稿；编辑会自动保留当前草稿，“保存布局”创建命名副本。第一版修改即时反映到浏览器内预览，没有“应用到手机”动作。

“26 键”只计算字母键，功能键另外统计；九宫格模板则有 8 个字母组和 1 个标点槽位。同样的字母键数量可以有不同的行数、每行数量、错行和左右分区；选定键数不应把所有几何锁死。

| 能力 | 交互原型 | 后续原生版本 |
| --- | --- | --- |
| 26 键的传统、正交、分体模板 | 可编辑、预览 | 第一批接入真实输入 |
| 9／14／18 键模板 | 演示槽位、字母组与尺寸；标明尚未接入解码 | 逐套验证字母分组与输入方案兼容性 |
| 从键库拖入、槽位互换、清空后回到键库 | 可操作；提供先选槽位再点键库的替代路径 | 保持相同规则，支持触摸与辅助功能 |
| 每行槽位数、传统错行开关、单键宽度比例、键高、间距和左右分区 | 实时预览；超出支持范围必须有说明 | 使用实际宿主宽度重新计算，增加整体宽度和左右对齐 |
| 自定义功能键 | 可放置和调整尺寸，演示本地试按结果 | 绑定删除、回车、空格、切换等已有行为 |
| 草稿、命名副本、恢复模板 | 本地保存；刷新后可恢复，修改即时预览 | 主 App 写共享配置，键盘扩展读取已应用版本 |
| 任意把多个字母合成一个键 | 不承诺中文候选；作为高级扩展预留 | 需要另行设计受限、可验证的解码器 |
| 并击模式 | 保持按键方案决定可用键集合的边界 | 独立适配，不被普通布局配置覆盖 |

## 数据模型先定下来

以下为建议的新模型，并非当前已有接口。原型可以使用等价 JSON；原生版再以共享 Swift 模型承载。

- **键定义**：稳定 `keyID`、显示标签、辅助功能名称、动作类型及参数。标签不是键身份，`空格` 和 `Space` 可以指向同一动作。字母键动作表示一个独立字母；共键动作表示一个字母组 ID，不能把 `ABC` 当作连续输入 `abc`。
- **槽位定义**：稳定 `slotID`、所在 `row`、`widthUnits`、行或分区 `offsetUnits`、横向跨度；预留纵向跨度并只开放已经实现的能力。槽位引用 `keyID`，空槽位也是合法的编辑状态。拖动键改变分配，拖动或修改槽位改变结构，两者分别处理。
- **行与整体几何**：行高比例、间距比例、左右分区间隔、外边距、整体宽度比例、左／中／右对齐。配置保存比例或逻辑单位；设备实际点数由宿主宽度与受限尺寸策略推导，不能保存某台手机截图上的绝对坐标。
- **布局版本**：`formatVersion`、`layoutID`、名称、来源模板及版本、草稿修订、已应用修订；每个输入方案可选择布局，布局同时声明独立字母或特定共键解码能力。
- **动作目录**：文字输入与功能动作分离。功能键引用固定动作 ID，例如删除、空格、回车、数字层、中英切换、系统下一键盘、Buffer、设置；不要允许原始脚本或任意调用。

## 分阶段交付与验收

### 阶段一：确认交互原型

交付当前目录中的独立交互页面。优先验证拖拽流程和参数是否直接影响预览，模板只是起点。

验收：

1. 从模板切入后，键库到空槽位、已占槽位交换、移回键库都有明确结果；拖动取消不能丢键。点选替代路径完成相同操作。
2. 槽位数、错行开关、单键宽度、键高、间距、边距、分区和功能键中，界面实际开放的每项配置均改变对应效果；未实现项不伪装成可操作项。
3. 缩减槽位数时保留被移出的键并显示待分配状态；不同键数模板之间切换不悄悄丢失用户草稿。
4. 保存命名副本、刷新恢复、恢复模板、撤销最近编辑有明确状态；恢复模板可撤销。当前草稿、命名副本与后续原生版的“已应用配置”互不混淆。
5. 编辑页与试按预览消费同一份布局数据；试按的字母、空格、删除和回车可在本地演示。共键只显示所触发字母组，候选不可用时明确说明。
6. 测试窄屏、常见手机宽度和横屏比例，空格加宽、功能键换位和紧凑度极值没有越界或遮挡；无效布局提示定位到具体行或槽位。
7. 原型的导出、保存和“应用”文案准确说明数据仅在浏览器／本地文件中；不让用户以为手机输入法已经改变。

用户确认编辑方式后再进入阶段二；阶段一不安装或替换手机输入法。

### 阶段二：原生 26 键与功能键

在主 App 增加布局编辑入口，先接入独立字母布局；支持传统、正交、分体与左右单手排列。真实输入仍走现有 Rime／英文通道。

验收：

1. 26 个字母覆盖完整；更换标签、重排和旋转后仍输入对应键动作。全拼、自然码双拼、英文分别验证，不用模拟输出冒充引擎结果。
2. 删除键移动后保留长按删除；空格保留光标操作；回车保留宿主语义；中英、数字层与 Buffer 操作正确；系统要求下一键盘按钮时始终保留可达入口。
3. 一个布局计算结果同时驱动总高度、显示框、命中区和辅助功能框。保持按键与边缘容错规则一致，分体中间空白不能吸附成键。
4. 复用并扩展现有 `KeyboardSizingTests`、`KeyboardLayoutTests` 和 `KeyboardInteractionTests`：首开临时大高度、同宽高度变化、横竖屏、候选展开、Buffer 开关、重新唤出均无顶部大空白或底部裁切。
5. 主 App 保存新布局时，正在进行的点击、长按、拖动或组字不被重新解释。当前交互继续使用冻结版本，待触摸结束且组字已提交／取消或新会话开始后切换。
6. 旧配置能加载；损坏、缺字段、未知动作和不兼容版本恢复最后有效布局，再以内置模板兜底。扩展只读，不增加对完全访问权限的依赖。
7. 在模拟器和真实手机的系统输入框、微信等宿主分别验证；源代码通过、模拟器通过、设备安装和真实输入验收分别记录。

### 阶段三：已知 9／14／18 键解码

先选定每套字母分组与支持的全拼／双拼方案，建立明确的兼容表。布局中的字母组 ID 交给相应解码适配器，所需 Rime 数据随构建产物打包。

验收：真实候选、选词上屏、退格、音节边界、模糊串消歧、中英切换和长句输入均正确；固定语料验证结果及失败案例；记录首开耗时、单键候选延迟和扩展内存，与阶段二基线比较后确定可接受阈值。移位不改变字母组含义，改变字母组需重新验证兼容性。

### 阶段四：高级自定义

根据前三阶段的反馈决定是否加入任意共键、按键层、长按／滑动分配、多行跨度、导入导出与更多模板。任意共键需要明确的复杂度上限、消歧策略和离线部署方案；不能仅靠模板 JSON 宣称支持。

## 校验与配置生效规则

- 保存草稿可以不完整，应用必须通过：ID 唯一、动作已知、必需字符有可达路径、必要功能可用、行列合法、几何有限且无重叠越界；按兼容表检查字母组与方案。
- 对最窄支持宽度和横屏分别校验可点击尺寸；给出具体修改建议。编辑器预览尺寸不应成为唯一通过依据。
- 主 App 先在内存中校验完整新快照，再原子写入；发布已应用修订与其完整数据，避免读到部分更新。最后有效快照和内置回退始终保留。
- 扩展按完整修订接收新配置并在安全边界切换，旧交互不能引用新映射。几何改变时冻结或退休旧触摸，不能把同一次按压投递到另一枚键。
- 恢复布局只影响布局数据，不重置用户词典、输入方案、AI 渠道或其他设置。
