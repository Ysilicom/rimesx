# 用户样包审计：键位布局与完整 Rime 方案导入

日期：2026-10-02。本文最初记录 build 23 布局导入阶段的只读样包审计，随后补充 build 24 的完整方案导入实现与兼容处理。初次审计没有执行脚本或部署方案；后续已通过独立方案服务对真实样包开展编译和引擎验证。下文 `文件:行号` 均指 ZIP 内条目，源码路径另行标明。

## 当前结论与阶段区别

这个包同时包含 **Rime 输入方案** 和 **Hamster（仓鼠）键盘界面配置**。主输入方案的 `schema_id` 是 **`xmjd6`**，`xingmao` 是随包仓鼠键盘配置中的布局名称。包内 `README.md:42–43` 将键道描述为“音＋韵＋辅助码”，辅助码对应五种笔画；不能把这个方案身份与键盘布局名称混用。

- **Build 23：布局导入。** 将可转换的仓鼠键位放进普通布局编辑器，报告未支持的手势等项目；当时没有安装星猫键道的编码、词典或 Lua 输入逻辑。
- **Build 24：独立完整方案导入。** [`RimeSchemeImportService.swift`](../../App/RimeSchemeImportService.swift) 检查、隔离暂存方案与依赖；主 App 协调编译、加载验证和原子发布，输入时使用受限 Lua。真实样包的主机探针已验证 `nkhz → 你好`、`fygl → 中国`、`ekjd → 世界`，以及 `nkhzn` 顶功提交「你好」并继续处理 `n`。这些属于实际引擎验证，不只是键位预览。

Build 24 的实现、测试层次和后续验收以[完整方案导入验证记录](../../validation/rime-schemes-20261002.md)为准。**本审计不确认 build 24 已安装到物理手机，也不把主机候选探针视作真机完整功能或手感验收。**

## Build 23 布局转换范围（继续保留的独立功能）

建议主 App 的“布局导入”支持 RIMES 自身版本化 JSON，以及 ZIP／YAML 中可识别的 Hamster `keyboards`。导入生成新副本，先预览、再应用。不能覆盖当前并击配置、输入方案、词库、其他偏好，也不能自动应用包内 `default.custom.yaml` 或 `hamster.custom.yaml`。

Build 23 已实现的转换器见 [`CustomLayoutImportService.swift`](../../App/CustomLayoutImportService.swift)。它支持原生／原型 JSON、仓鼠 YAML，以及 ZIP 中的 `hamster.yaml`／`hamster.custom.yaml` 显式布局列表；只转换完整 26 字母主布局，其他布局进入识别报告。Swift 实际读取本样包后得到 `xingmao` 草稿，共 31 键、四行 10／9／9／3；由于原配置没有独立中英切换键，需先在编辑器补齐才能应用。实际检查识别到 70 项滑动、36 项菜单、2 个边缘动作及数字层横屏超宽，均明确报告。这个布局入口本身仍不会安装 Rime 方案，完整方案使用另一入口。

布局解析器有意只支持有界的 YAML 子集：缩进式结构和单行流式集合、单行引号；跨行引号／方括号或引号混入未加引号的文本会提示调整格式。支持样包的样式锚点引用与 YAML 1.1 中未加引号的 `=`；未知标签、重复键、复杂引用和过深结构会被拒绝。ZIP64、分卷、加密 ZIP 暂不支持。这些是布局解析器的限制；build 24 的方案解析器另以 libyaml 事件流检查层级和节点预算，支持正常的多行方案 YAML，不能将两者混为通用导入规范。

## 找到了什么键盘

`hamster.yaml:64–1502` 包含两个明确命名的键盘，不是只有皮肤参数。

| 布局 | 主键内容 | 附加行为 | 来源 |
| --- | --- | --- | --- |
| `xingmao` | 四行，条目数 10／11／9／3；26 个 QWERTY 字母、2 个 `characterMargin`、Shift、删除、数字层、空格、回车 | 70 项滑动动作、36 项长按菜单动作 | `hamster.yaml:64–1009` |
| `123` | 四行，每行 6 项；19 个数字／符号字符键、删除、两种键盘切换、空格、回车 | 35 项滑动动作 | `hamster.yaml:1010–1502` |

数字／符号布局应被识别并展示在导入报告中；第一版若只开放普通字母布局，必须明确它尚未应用，不能把它当作另一套完整 26 键布局。

典型主键是 `action.character.char: q`，宽度是 `width.percentage: 0.1`，标签是 `label: q`，见 `hamster.yaml:69–74`。因此主字母键的位置、字母动作和相对尺寸有直接转换基础。标签和实际输入动作必须分开保存。

`xingmao` 声明 `isPrimary: true`（`hamster.yaml:65–66`），但另一文件将 `keyboard/useKeyboardType` 设置为内置 `chinese`（`hamster.custom.yaml:45–50`）。这份静态包不能单独证明作者设备当前实际启用哪套键盘；导入页应让用户选择识别出的布局。

## 转换边界与已发现的陷阱

| 项目 | 样包证据 | 第一版处理要求 |

| 字母、Shift、删除、空格、回车 | `hamster.yaml:69–74,615–620,881–887,959–986` | 转成固定动作目录；移动位置后仍复用既有行为，不按显示标签猜动作 |
| 数字层／指定键盘切换 | `hamster.yaml:918–925,1404–1412` | 区分切到导入的 `123` 与 RIMES 自带数字层；若只接到内置数字层，报告这一转换差异 |

| 按键内边距 | `hamster.yaml:1003–1007,1502` | 有按方向指定的对象，也有统一数值；映射到编辑器对应参数，否则列出未保留项 |
| 上下左右滑动 | `hamster.yaml:75–91,314–329,888–915` | 存在字符输入、方向键、清空和重输；不支持的动作不能静默变成普通点击 |
| 长按菜单 | `hamster.yaml:115–160,644–654` | 既有直接文本，也有方案切换；第一版未开放时列出数量和类型 |
| Rime 处理与直接输入 | `hamster.yaml:970–978,1444–1458` | `processByRIME` 有 true／false，不能统一当作直接插字；布局导入不应改变引擎语义 |

## 为什么 Build 23 的布局导入不能等同完整方案导入

这份方案的 Lua 不全是装饰。

- 顶功处理器直接决定何时提交已有候选、清空或继续编码：`xmjd6.schema.yaml:113–115`、`lua/xmjd6/xmjd6_topup_processor.lua:14–20,71–101`。去掉它会改变标题所指的核心“顶功”行为。
- 空码回退、连打中的空格／分隔符处理也由 Lua 实现：`xmjd6.schema.yaml:109,115`、`lua/xmjd6/auto_fallback.lua:1–7`、`lua/xmjd6/sentence_buffer.lua:1–3,20–34`。
- 统计、计算、日期等工具是可以单独评估取舍的附加能力（`xmjd6.schema.yaml:137–150`），但静默删除全部 Lua 会连同主要输入行为一起丢掉。甚至统计处理器还会拦截特定命令的数字输入，见 `lua/xmjd6/key_counter.lua:19–21`。
- 包里还有桌面应用启动器，注册于 `xmjd6.schema.yaml:101,137`；实现含桌面命令和 `os.execute` 调用，见 `lua/xmjd6/app_launcher.lua:21–46,125–138`。这些是待审查的外来代码，审计中未执行，也不是移动键盘布局动作。

以下是 **build 23、尚未接入完整方案导入时的历史架构边界**，不是 build 24 的当前能力：

- 当时 [`MobileEngine.swift`](../../Support/MobileEngine.swift) 只从 App 包内 `EngineData/build` 初始化，用户目录是进程自身的 Application Support。
- 当时 [`RimeMobile.mm`](../../Bridge/RimeMobile.mm) 将 prebuilt/staging 指向包内 build，没有用户方案部署入口。
- 当时构建脚本禁用外部插件，资源校验排除 `.lua`；这一限制已由 build 24 的受限 Lua 集成和独立方案部署链路扩展。

Build 24 已补齐独立方案检查、依赖闭包、主 App 内编译和加载验证、隔离发布与受限 Lua；键盘扩展仍不在首次打开时编译方案。部署、启用是分别操作，方案发布不会自动覆盖或切换现有并击。仅把 YAML／词典拷贝到布局目录仍不等同完成这些步骤。

方案导入将可用 schema、schema 专属补丁、词典、Lua 和 OpenCC 资源放入独立目录；包内全局 `default.custom.yaml`、安装标识和仓鼠／小狼毫等界面配置不会覆盖本机配置。隔离的 `default.yaml` 只保留必要预设并写入用户所选方案列表。检验失败不发布，具体证据与未完成项见[build 24 验证记录](../../validation/rime-schemes-20261002.md)。

## 布局导入实现的验收重点

1. 原生 RIMES JSON 导出再导入，键身份、动作、行结构、尺寸和名称不丢失；不把标签当动作。
2. 本样包能识别两个 Hamster 布局，至少生成可审阅的 `xingmao` 普通 26 键副本，并准确列出滑动、菜单、数字层及边缘行为的处理结果。
3. 对 ZIP 设置条目数、单文件／展开总大小上限；拒绝路径逃逸、符号链接、同名覆盖和超限展开。只读必要的配置条目，不展开或执行 Lua、脚本或外部引用。
4. 不支持的 JSON 版本、YAML 类型、别名循环、非法尺寸、未知动作、横屏越界均有具体诊断；失败不得破坏已有配置。
5. 普通布局应用与现有并击路径隔离，仍执行 [`PLAN.md`](PLAN.md:5) 中的并击兼容要求。方案导入与布局导入在文案、状态和存储上分别处理。

样包清单及文件结构来自静态审计；build 24 的实际编译、候选和顶功测试属于额外取得的运行证据。安装版本、真机输入及手感应继续分别验收，不从静态审计或主机探针推断。
